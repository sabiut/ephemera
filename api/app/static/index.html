What your app needs

  • A docker-compose.yml in the repository root.
  • A web service with ports:. That is the link reviewers open.
  • An image per commit in a public registry. Ephemera runs images; it doesn't build them. The dashboard generates the GitHub Actions workflow that does.
  • Databases, caches and queues run inside the preview, reachable by their compose names. Their data isn't kept.

Where previews run

  • On Ephemera's Kubernetes cluster on Google Cloud, each pull request in its own isolated namespace.
  • Each preview is limited to {{PREVIEW_CPU}} CPU, {{PREVIEW_MEMORY}} of memory and {{PREVIEW_PODS}} pods.
  • Preview links are public: anyone with the link can open one. Don't put real secrets or customer data in a preview.
  • The dashboard shows a preview to its PR's author and to the repository's collaborators.

Try the sample app

ephemera-test-app is a small web app already set up for Ephemera: it builds an image for every commit and serves a page showing which commit it runs.

  1. Fork the sample app to your GitHub account.
  2. In your fork, open the Actions tab and enable workflows. GitHub turns them off in new forks.
  3. Install the Ephemera GitHub App on your fork, then sign in.
  4. On a new branch, change the message in index.php and open a pull request in your fork.
  5. The first build creates the image package in your account, and it starts out private. Make it public: Packages, then Package settings, then Change visibility. Then click Retry preview on the dashboard.
  6. Open the link Ephemera posts on the pull request. From now on, every push updates it by itself.

Free during the beta

Ephemera is in beta. It's free while it is, features may change, and every preview is removed when its pull request closes. Signing in only shares your GitHub profile and email address; repository access comes from the GitHub App you install on the repositories you choose.
